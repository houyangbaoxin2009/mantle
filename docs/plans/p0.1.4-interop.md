## 决定 / Decision

**通信栈语言分工（Decision）**：`std/tink_v2`（tie 标准库，命名空间 `tink2`）为**协议权威**；
Subterra `engine.network`（Java 只读基准）为**同规格参考实现**；两者由两条机械约束互锁——

1. **字节级线格式**（权威，勿改）：
   `[magic 0x74 0x6B][v=2][flags][len u32 BE][ext_len u16 BE][ext TLV][payload][integrity]`；
   flags bit0 = STRONG（1→32B 槽 / 0→8B 槽），保留位 bit5..7 须为 0；首两字节非 magic → v1 兼容读。
   快校验 = ASCII 字节 of `tsha1f(payload,8,48)`（8 字节）；强档 = `digest(f,payload,48)` hex→bytes 前 32。
2. **权威金向量**（跨语言对等契约；本探针 tie 与 Java **各自自证一致**）：
   - `tsha1f("",8,48)="5juavlyl"`
   - `tsha1f("123456789",8,48)="3Kz1piuc"`
   - `tsha1f("abc",8,48)="5FGIxu1J"`
   - `tsha1f("a"*64,8,48)="5juavlyl"`
   - `digest("f","123456789",48)` 全宽 hex 前 64 字符 = `260c7340bcc60eb82c727e6df6f9c7620d040c2d4837ee96dc333f1a16fd76bf`

**p.0.4 采用**：Mantle 可任取 tie 或 Java 一侧（或两者）承载网络帧。本探针已证 tie 编码的帧与
Java 参考实现输出**逐字节相同**（`dir1` 字节级一致），故在 p.0.4 选路时切换代价 ≈ 0。决策矩阵：
tie 栈内联优先（zrpc/LSP/桥）→ tie；纯 JVM 生产部署 → Java；混合混接（任一侧编、另一侧解）无缝。

EN: std/tink_v2 (tie std, namespace `tink2`) is the protocol authority; Subterra engine.network
(Java, read-only baseline) is the same-spec reference implementation. Interop is pinned by two
mechanical constraints: byte-level wire format + the authoritative golden vectors. For p.0.4 either
side (or both) may host network frames with near-zero switching cost (proven byte-identical here).

## 实现要点 / Implementation notes

* **Java 参考实现** `FfmInteropProbe.java`：内置 tsha1f f 模型最小参考 + 快校验帧编解码，
  七项自检（5 金向量 + 2 方向），纯 JVM、无仓库依赖；`-DtieProbe=` 指向 tie 编译出的 `probe.exe`。
* **tie 探针** `tie_side/probe.tie`：直接消费 vendored `std/tink_v2.frame_encode` / `frame_next`
  （快校验），并 `tsha1f` / `tsha1_digest` 自证金向量；经 stdin/stdout 行协议与 Java 驱动对话。
* **可移植构建**：`tie_src/` 逐字镜像 tie-main std（TPL 2.0，见 `NOTICE.md`），免跨仓库 import，
  尤免拉入 tsha1 的 `tsha1_w48.tie`（~774KB）。已确认无需 `.a` 归档，镜像保持精简。
* 确定性：无墙钟断言，全部按字节/常量比对。
