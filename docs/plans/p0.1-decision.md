## p.0.1.1 tie 并发能力摸底 → region 调度底座结论 / tie concurrency → region-scheduler base

**结论（建议）**：Mantle region 调度底座 = **trm-lite 复杂形态（import tl_runtime_ctx）**；
简单形态内置原语（spawn/yield/collect + ch_* + wg_* + gosched）为轻量替代路径；
actor（1:1 + mailbox）作强隔离备选。Java 21 壳只保 MC 补丁层 + 生态加载桥。

### 能力清单（landed per README preview.3 / CHANGELOG）
* 复杂形态（import tl_runtime_ctx）：ctx_ensure / ctx_set_workers(默认 4，首 drain 前设置) /
  ctx_spawn → 任务 id / ctx_queued / ctx_drain（**常驻池**，首 drain 起池、ctx_shutdown join 销毁，
  worker 限时存活不每轮重建）/ ctx_gosched（协作抢占 + 时间片 S_SLICE_LIMIT=8）/
  ctx_pool_threads / ctx_shutdown / ctx_collect（并发三色 GC + 分代 + mark-compact）/
  ctx_stolen / ctx_completed / ctx_ch_*（channel：open/send/recv/close/len/count/select 多路）/
  ctx_wg_*（WaitGroup，Go 语义，done 归零广播）/ ctx_version。
* 简单形态（内置，零 import）：spawn/yield/collect、ch_open/send/recv/close/select、gosched、
  wg_new/add/done/wait/count——S-pool（p.6.7.6）同样真并行常驻池。
* 语言层：actor 原生语法（1:1 OS 线程 + mailbox 串行免锁，m6_actor 全套）；
  atomic<i64>（store/load/fetch_add/cmpxchg）；race 纪律 S1–S4（原子计数 / 独立槽位 / 锁保护复合态 /
  运行时容器安全），U1–U6 不安全模式；并发断言禁墙钟、主证 = tid 去重 ≥ 2。

### 已知限制（preview.3，诚实清单）
* 任务 = fn() -> i64 原子体；协作抢占非 OS 硬抢占（两个让出点间不可打断）；可迁移 = 任务与 worker 解耦计数，非 OS 协程栈迁移。
* channel 消息为标量 i64；ch_recv 空返回 0 / ch_send 队满返回 1（非阻塞降级，Go 阻塞语义需轮询/cv 协商）；ch_close 已按 Go 广播唤醒。
* 精确根 = 任务 env 保守口径；老 demo 时序断言受宿主噪声偶发 FAIL（验收以确定性探针 + stdout 逐字节一致为准）。
* 简单/复杂形态互斥（同程序混用 → tiec 报错）；actor 与 import trm-lite 混用 → 报错。
* tie 既有缺陷沿用：标量全局初值静默丢弃、to_string(bool) 输出 -1/0、单行块须 `;`、顶层 table 全局须 `= []`。

## p.0.1.3 生态加载桥摸底（web 调研定稿）

### NeoForge 宿主接缝清单（线程化核心影响）
| 接缝 | 依赖 vanilla 类/事件 | 线程化核心影响 | 结论 |
|---|---|---|---|
| 注册表时序 | RegisterEvent / mod 总线（启动期一次） | 启动仍单线程，冻结点不变 | 存活 |
| 全服 tick | ServerTickEvent(Pre/Post) | 无单一主 tick，需在全局区合成 | **破** |
| 每实体/区块 tick | Entity.tick / BlockEntity.tick / level tick 循环 | 改区域线程派发 | 幸存（改派发） |
| 区块/实体事件 | BlockEvent / EntityEvent / LivingEvent | 所属区域线程触发；跨区处理器竞态 | 幸存（带域约束） |
| 等级存储/存档 | level/chunk 存储钩子 | 按区域惰性 | 幸存（适配） |
| 网络 payload | payload 注册/编码 | 跑全局调度器 | 幸存 |
| Capability/附件 | 每对象数据 | 需线程亲缘 | 幸存（受限） |
> 佐证：C2ME 后台线程触发的 `finalizeMobSpawn` 事件内 `Level.isRainingAt→getChunkAt` 阻塞致整服冻结 121s——mod 普遍假设「主线程单线程可安全阻塞加载」。

### Fabric 适配层裁定（Connector 式）
* Connector 三层：discovery（ConnectorLocator）→ transform（JarTransformer + BytcodeFixerUpperFrontend 把 Intermediary 引用重映射为 NeoForge 映射）→ load（加载器服务 + DummyVirtualJar + FFAPI 端口 + mixin 经 MixinPatchTransformer）；注册表桥靠自带 mixin（RegistryDataLoaderMixin / PoiTypesMixin / NetworkRegistryMixin）。
* **关键判断**：Connector 只做「API/命名翻译」，**不做并发模型翻译**——线程化下最大缺口。
* Top-3 冲突：① mixin 注入点/映射命名空间（线程化重构改 ServerLevel.tick 等内部名 → refmap 失效）；② 单服务端线程假设（Fabric API S_ERVER_TICK 回调）；③ 注册表冻结时序倒挂（NeoForge 冻结后 Fabric 懒注册崩，现靠 mixin 补救）。
* 裁定：启动期可行，**运行时 tick/mixin 层需按区域重改（高成本）**。

### Forge 路线仲裁（决策项，交用户）
* 事实：NeoForge = 2023-07-12 Forge 分叉；1.20.1 是唯一近乎互通窗口；1.20.2 起包名 `net.minecraftforge→net.neoforged` 彻底分化（mods.toml→neoforge.mods.toml）；FML 1.20.1 生命周期并行派发、enqueueWork 序不确定。
* 选项：(a) 版本窗口对齐（仅 1.20.1 legacy parity，目录庞大 ATM9/DawnCraft，桥最小）；(b) 全量桥（造价≈第二个拆分加载器全套，风险高、无 clean-room 收益）；(c) **暂缓（推荐）**：先做 NeoForge 主线 + Fabric 适配验证，再回头评估 1.20.1 窗口。
* **建议**：采纳 (c) 暂缓；留 (a) 为后续备选。

### Paper 插件 executor 约束清单（设计先例，非代码）
区域并行隔离（严禁跨区读写）、弃用 BukkitScheduler → 提供 4 类调度器（RegionScheduler 位置亲缘 / EntityScheduler 实体亲缘 / AsyncScheduler 线程池 / GlobalRegionScheduler 全局）、写世界数据前线程上下文校验、未标记 `folia-supported:true` 拒绝加载、区域调度任务区块卸载取消（cancelIfUnloaded）、跨区通信仅经线程安全消息禁共享可变状态。

## p.0.1.2 语言间 ABI 冒烟结论（abi-smoke/，commit 9cb3307）

* 采用形态：**简单形态（builtin spawn/ch_*/wg_*）回退**，DLL 探针全绿
  （completed()=24 / wg 3→0 / channel 顺序收发 1..5 / ch_close 后 recv=-1 / fail_count=0 / 版本码 0x00030000=preview.3）。
* **三项实测边界（开放工具链缺陷/约束，p.0.2+ 需治）**：
  1. **复杂形态（import tl_runtime_ctx）注入 DLL 被导出面校验拒绝**：`trm_lite_ws::spawn` 参数
     `fn()->i64` 不能跨动态库边界 → 复杂运行时目前只能活在 tie 独立进程/exe，不能经 DLL 由 Java 起调度；
  2. **tiec `--shared` 不自动链接 trm_lite.a**（link_shared 漏传 g_used_trmlite；需 `clang -shared` 手工链）→ 编译器补参即可消除；
  3. 简单形态 DLL 为协作式单线程（poolThreads()=1），「≥2 OS 线程」并行证据在跨 DLL 路径不可得。
* **架构结论**：**线程并行必须活在 tie 进程内部；Java FFM 仅作标量指令通道**（发启动/查询指令、读回 i64 结果）。Mantle p.0.3 region 调度 = 独立 tie 进程/运行时承载并行（而非经 FFM 起线程）；Java 壳经 FFM 或 IPC 与该进程协作。
* 细节证据见 abi-smoke/README.md（复现：`cd abi-smoke && ./build-run.ps1`）。

## p.0.1.4 通信栈取舍与跨语言一帧互通（abi-smoke/interop/，commit 3d572e07）

* **决定**：`std/tink_v2`（tie）= **协议权威**；Subterra `engine.network`（Java）= 同规格参考实现；
  互锁约束 = **字节级线格式 + 权威金向量**（tie 与 Java 各自自证 5 条一致）。
* 证据：Dir1 Java→tie `ok=1 iok=1` 且帧逐字节相同；Dir2 tie→Java parse/payload/tsha1f 全等；
  金向量 `""→5juavlyl`、`"123456789"→3Kz1piuc`、`"abc"→5FGIxu1J`、`"a"*64→5juavlyl`、strong `260c73…76bf`。
* 结论：p.0.4 任选 tie / Java / 混接承载网络帧，切换代价 ≈ 0。
  （复现：`cd abi-smoke/interop && ./build-run.ps1`；决策段全文见归档本段。）
